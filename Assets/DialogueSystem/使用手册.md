# DialogueSystem 对话节点编辑器使用手册

本文档适用于 `Assets/DialogueSystem`。它说明如何创建对话图、编辑节点、添加事件，以及为**选择节点中的每一个选择**配置条件。

> 当前版本的职责划分：
> - `DialogueNode`：负责说话者和对话文本。
> - `ChoiceNode`：只负责选项和选项条件，不再包含 `Speaker Name`、`Dialogue Text`。
> - 如果需要“先说一段话，再让玩家选择”，请把一个 `DialogueNode` 连到 `ChoiceNode`。

---

## 1. 安装与打开编辑器

1. 将整个 `Assets/DialogueSystem` 文件夹复制到 Unity 工程的 `Assets` 目录下。
2. 等待 Unity 编译完成，确认 Console 没有红色编译错误。
3. 在 Project 窗口空白处右键，选择：

   `Create → Dialogue System → Dialogue Graph`

4. 双击创建出来的资产，打开 `Dialogue Graph` 编辑器。
5. 也可以通过菜单打开：

   `Window → Dialogue System → Dialogue Graph`

6. 如果使用菜单打开，先在窗口顶部的“对话资产”栏中拖入一个 `Dialogue Graph` 资产。

### 保存方式

- 新建节点、移动节点、连线、修改字段都会让顶部状态变成“有未保存修改”。
- 点击顶部的“保存”按钮，或在 **GraphView 图区域内**按 `Ctrl + S`（macOS 为 `Cmd + S`）保存。
- 切换对话资产或关闭窗口时，如果还有未保存修改，编辑器会询问是否保存。
- “聚焦全部”按钮可以让右侧图视图自动显示所有节点。

### 复制与粘贴节点

- 选中一个节点后按 `Ctrl + C`（macOS 为 `Cmd + C`）：深拷贝该节点的**全部内容**（说话者、正文、选项及条件、事件配置、等待时间等所有字段）。
- 把鼠标移到目标位置后按 `Ctrl + V`（macOS 为 `Cmd + V`）：在鼠标所在位置粘贴出一个新节点（自动生成新 guid，与原节点完全独立）。
- 可以**连续多次** `Ctrl + V`：每次粘贴都是独立克隆，互不影响。
- **开始节点无法复制**：它是全图唯一入口，选中它按 `Ctrl + C` 会提示并拒绝。
- 复制/粘贴只在当前图编辑器会话内有效（不经过系统剪贴板，也不跨窗口）。

## 2. 节点类型与推荐连接方式

| 节点 | 作用 | 输出端口 |
| --- | --- | --- |
| 开始 | 固定入口，每张图唯一，不可删除 | 下一个 |
| 对话 | 显示说话者和一段对话文本 | 下一个 |
| 选择 | 显示多个选项，每个选项一个端口 | 每个选项一个 |
| 状态分支 | 按条件从上到下选择第一条命中的分支 | 每条分支 + 默认 |
| 随机分支 | 在所有满足条件的分支中随机走一条 | 每条分支 + 默认 |
| 事件 | 每个事件类型一种独立节点，执行一个事件 | 下一个 |
| 等待 | 等待指定秒数后继续 | 下一个 |
| 跳转 | 跳转到另一张对话图的入口 | 无 |
| 结束 | 明确结束当前对话 | 无 |

### 最常见的对话结构

```text
开始 → 对话 → 选择
              ├─ 选项 0 → 对话 → 结束
              ├─ 选项 1 → 事件 → 对话 → 结束
              └─ 选项 2 → 结束
```

选择节点本身不再保存说话者和对话文本。因此推荐这样组织：

```text
对话节点(“村长”：你想做什么？) → 选择节点(接取任务 / 离开)
```

这样每个节点只承担一种职责，详情面板也更清晰。

### 创建和连接节点

1. 在右侧图区域空白处点击右键。
2. 在“创建对话节点”菜单中选择节点类型。
3. 拖动节点的输出端口到另一个节点的输入端口。
4. 普通节点的输入端口支持多个前置节点，适合多个分支汇合到同一个节点。
5. 选择节点和状态分支节点的输出端口顺序与左侧列表顺序一致，修改列表顺序后请检查连线。
6. 删除连线：选中连线后按 `Delete`。
7. 删除普通节点：选中节点后按 `Delete`。开始节点由编辑器保护，不能删除。
8. 复用相似节点：选中节点 `Ctrl + C`，鼠标移到目标位置 `Ctrl + V`（详见上文“复制与粘贴节点”）。

## 3. 对话节点：编辑说话者和正文

1. 点击图中的“对话节点”。
2. 在左侧“节点详情”中填写：
   - `Speaker Name`：说话者名称，例如“村长”“商人”。
   - `Dialogue Text`：对话正文。
   - `Voice Clip`：可选语音片段。
3. `Dialogue Text` 会根据输入内容、换行和自动换行结果自动增高。
4. 文本框有最小高度，不会因为内容较短而缩得过小；输入长段落时会继续扩展。
5. 点击保存。

### 文本编辑建议

- 一段独立显示的台词使用一个 `DialogueNode`。
- 不要把多个不同角色的台词塞进同一个节点；这样无法逐句控制玩家点击“继续”的时机。
- 需要换行时可以直接在 `Dialogue Text` 中按 Enter。
- 需要选项提示时，先用对话节点显示提示，再连接选择节点。

## 4. 选择节点：添加选项

选择节点的详情面板只显示 `Choices` 列表，不显示 `Speaker Name` 和 `Dialogue Text`。

### 添加一个选择

1. 创建一个 `ChoiceNode`。
2. 点击选择节点，在左侧找到 `Choices`。
3. 展开 `Choices` 列表。
4. 点击列表右下角的 `+` 添加一个 `ChoiceOption`。
5. 在新增元素的 `Choice Text` 中输入玩家看到的文字，例如：
   - `接取任务`
   - `去商店`
   - `离开`
6. 再次点击 `+` 可以继续添加更多选择。
7. 选择列表的下标就是输出端口编号：
   - 第 0 个选择 → 输出端口 0
   - 第 1 个选择 → 输出端口 1
   - 第 2 个选择 → 输出端口 2
8. 将每个输出端口分别连接到对应的后续节点。
9. 保存。

### 选择条件的基本规则

- 每一个 `ChoiceOption` 都有自己独立的 `Conditions` 列表和“**条件组合**”下拉。
- `Conditions` 为空：该选择无条件，始终显示。
- 条件组合为**并（All，默认）**：所有条件都满足时才显示。
- 条件组合为**或（Any）**：任一条件满足即显示；列表中的空元素会被忽略。
- 条件不满足时，运行时会隐藏该选择，但不会改变其他选择的下标。
- 回调使用的是原始选择下标，所以隐藏选项不会导致后续连线错位。
- 如果运行时没有任何选择满足条件，对话会结束。若需要兜底路线，建议使用状态分支节点或添加一个无条件的“离开/返回”选项。

### 给某一个选择添加条件

以“去商店，金币至少 50”为例：

1. 点击选择节点。
2. 展开 `Choices`。
3. 展开要限制的那个 `ChoiceOption`。
4. 在该选项的 `Conditions` 区域点击 **添加条件**。
5. 在弹出的类型菜单中选择 `IntCompareCondition`。
6. 设置：
   - `Key` = `gold`
   - `Op` = `GreaterOrEqual`
   - `Value` = `50`
7. 保存。
8. 运行对话前，游戏代码需要把当前金币写入上下文：

```csharp
var context = new DialogueContext();
context.Blackboard.SetInt("gold", 100);
player.Play(dialogueAsset, context);
```

此时金币为 100 时“去商店”显示；金币为 49 时该选择隐藏。

### 给同一个选择添加多个条件

例如“只有金币至少 50 且任务已经完成”才能选择：

```text
ChoiceOption: 去商店
└─ Conditions
   ├─ IntCompareCondition: gold >= 50
   └─ QuestStateCondition: shop_quest == Completed
```

操作步骤：

1. 在同一个 `ChoiceOption` 的 `Conditions` 区域点击 **添加条件**，添加第一个条件。
2. 再次点击同一个区域的 **添加条件**。
3. 添加第二个条件。
4. 两个条件都会满足时，这个选择才会显示。

不要把条件加到另一个 `ChoiceOption` 上；每个选项的条件列表是独立的。

## 5. 内置条件的写法与使用

### 5.1 `IntCompareCondition`：比较整数

用于金币、分数、等级、好感度、计数器等整数值。

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `Key` | 黑板整数的键 | `gold` |
| `Op` | 比较运算符 | `GreaterOrEqual` |
| `Value` | 比较目标值 | `50` |

可用运算符：

| 枚举值 | 实际含义 |
| --- | --- |
| `Equal` | `==` |
| `NotEqual` | `!=` |
| `Less` | `<` |
| `LessOrEqual` | `<=` |
| `Greater` | `>` |
| `GreaterOrEqual` | `>=` |

运行时代码示例：

```csharp
context.Blackboard.SetInt("gold", 100);
context.Blackboard.SetInt("player_level", 8);
```

编辑器配置示例：

```text
Key = player_level
Op = GreaterOrEqual
Value = 5
```

含义是：玩家等级大于等于 5 时满足。

### 5.2 `BoolFlagCondition`：比较布尔标记

用于门是否打开、是否看过某段剧情、是否拥有某个能力等。

```text
Key = talked_to_guard
Expected Value = true
```

运行时代码：

```csharp
context.Blackboard.SetBool("talked_to_guard", true);
```

条件含义是：`talked_to_guard == true`。

### 5.3 `QuestStateCondition`：判断任务状态

可选状态：

- `NotStarted`：未接取
- `Active`：进行中
- `Completed`：已完成

编辑器配置示例：

```text
Quest Id = dragon_quest
Required Status = Completed
```

运行时代码或事件可以写入任务状态：

```csharp
context.Quests.AddQuest("dragon_quest");
context.Quests.CompleteQuest("dragon_quest");
```

任务 ID 必须完全一致，包括大小写和下划线。

## 6. 事件节点：每个事件类型是一种独立节点

事件节点在运行时自动执行它持有的一个事件，然后从“下一个”端口继续。

**每个 `DialogueEvent` 子类（接取任务 / 完成任务 / 设置整数 / 你的自定义事件）都是一种独立的图节点**，节点标题就是事件类型的显示名。

### 创建事件节点

1. 在图中空白处点击右键。
2. 找到“**事件节点**”分组并展开。
3. 分组下会列出**所有**事件类型（自定义事件子类编译后自动出现），每选择一个类型就创建一个对应的事件节点。
4. 也可以选择“空白事件节点(创建后再选类型)”，创建一个未指定类型的节点，稍后在详情面板选择。
5. 填写事件字段，将“下一个”端口连接到后续节点，保存。

### 更换事件类型

选中事件节点后，详情面板顶部有“**事件类型**”下拉：

1. 点击下拉按钮，弹出所有可用事件类型。
2. 选择新类型后，节点立即切换为新事件（**原事件的字段配置会被重置**，请谨慎操作）。
3. 节点标题和摘要随之更新。

### 自定义事件类型的节点颜色

选中任意事件节点后，详情面板中有“**节点颜色**”一行：

1. 点击颜色框打开拾色器选色。
2. 颜色**按事件类型全局生效**：给“接取任务”设定颜色后，所有接取任务节点都会变成这个颜色。
3. 未自定义时显示“(自动)”——系统按类型名自动分配一个稳定颜色，同类型永远一致。
4. 点击“**恢复自动**”按钮可清除自定义色，回到自动分配色。
5. 颜色保存在本机编辑器偏好中，**不随对话资产迁移**，换电脑后需要重新设置。

### 6.1 `AddQuestEvent`：接取任务

在“事件节点”分组下选择“接取任务”，创建节点后设置 `Quest Id`（例如 `dragon_quest`）。运行到该节点时，相当于：

```csharp
context.Quests.AddQuest("dragon_quest");
```

### 6.2 `CompleteQuestEvent`：完成任务

在“事件节点”分组下选择“完成任务”，设置与接取任务时完全相同的 `Quest Id`。运行到该节点时，相当于：

```csharp
context.Quests.CompleteQuest("dragon_quest");
```

### 6.3 `SetIntEvent`：设置整数

在“事件节点”分组下选择“设置整数”，设置：

- `Key` = `gold`
- `Value` = `0`

运行到该节点时，相当于：

```csharp
context.Blackboard.SetInt("gold", 0);
```

> `SetIntEvent` 是“直接设置”，不是“增加或减少”。如果需要 `gold += 10`，请编写自定义事件，或在自己的游戏状态系统中实现对应逻辑。

### 6.4 连续执行多个事件

需要一次执行多个事件时，把多个事件节点**串联**起来即可：

```text
[完成任务] → [设置整数 gold=100] → 下一个节点
```

执行顺序就是连线顺序。如果后续节点的条件依赖前一个事件修改的状态，把修改状态的事件节点放在前面。

## 7. 编写自定义事件

当内置事件不能满足需求时，继承 `DialogueEvent`。自定义事件必须满足：

- 类使用 `[Serializable]`。
- 继承 `DialogueEvent`。
- 实现 `Execute(DialogueContext context)`。
- 文件放在工程 `Assets` 下并成功编译。
- 类不是抽象类，并且可以被 Unity 序列化。

编写完成并编译后，你的自定义事件会**自动出现在右键菜单的“事件节点”分组下，成为一种独立的图节点**，与内置事件（接取任务/完成任务/设置整数）用法完全一致。

### 示例：增加金币

将下面脚本保存为：

`Assets/Scripts/Dialogue/AddGoldEvent.cs`

```csharp
using System;
using DialogueSystem;

[Serializable]
public class AddGoldEvent : DialogueEvent
{
    public int amount = 10;

    public override void Execute(DialogueContext context)
    {
        var current = context.Blackboard.GetInt("gold");
        context.Blackboard.SetInt("gold", current + amount);
    }

    public override string GetSummary()
    {
        return $"金币 += {amount}";
    }
}
```

### 示例：设置布尔标记

```csharp
using System;
using DialogueSystem;

[Serializable]
public class SetFlagEvent : DialogueEvent
{
    public string key;
    public bool value = true;

    public override void Execute(DialogueContext context)
    {
        context.Blackboard.SetBool(key, value);
    }

    public override string GetSummary()
    {
        return $"{key} = {value}";
    }
}
```

### 示例：调用自己的游戏系统

如果项目中有任务管理器、背包系统或剧情管理器，可以在 `Execute` 中调用它们：

```csharp
using System;
using DialogueSystem;

[Serializable]
public class UnlockDoorEvent : DialogueEvent
{
    public string doorId;

    public override void Execute(DialogueContext context)
    {
        // 替换为项目实际的门系统调用。
        // DoorManager.Instance.Unlock(doorId);
    }

    public override string GetSummary()
    {
        return $"解锁门[{doorId}]";
    }
}
```

> `Execute` 是运行时调用，不是在编辑器里点击 `+` 时执行。编辑器中的字段只是把事件数据保存到对话资产。

### 自定义事件添加不到菜单时

按以下顺序检查：

1. Console 是否有红色编译错误。
2. 类是否继承了正确的 `DialogueSystem.DialogueEvent`。
3. 是否加了 `[Serializable]`。
4. 类是否为 `public`、非 `abstract`。
5. 脚本是否放在 `Assets` 目录下。
6. 保存脚本后等待 Unity 编译完成，重新打开右键菜单的“事件节点”分组查看。
7. 如果事件类名或命名空间已经被改过，旧的 `[SerializeReference]` 数据可能无法恢复；正式项目应使用 Unity 的 `MovedFromAttribute` 做兼容迁移。

## 8. 自定义节点、条件和事件的编辑器名称

默认情况下，Unity 会使用 C# 类名作为类型名称。为了避免在 GraphView、条件列表和事件类型菜单中直接看到类名，可以给自定义类型添加 `DialogueEditorName` 特性。

```csharp
using System;
using DialogueSystem;

[Serializable]
[DialogueEditorName("增加金币", "把玩家金币增加指定数量")]
public class AddGoldEvent : DialogueEvent
{
    public int amount = 10;

    public override void Execute(DialogueContext context)
    {
        var current = context.Blackboard.GetInt("gold");
        context.Blackboard.SetInt("gold", current + amount);
    }

    public override string GetSummary()
    {
        return $"增加金币 {amount}";
    }
}
```

配置完成并成功编译后，编辑器会使用：

- `增加金币` 作为事件类型名称
- `把玩家金币增加指定数量` 作为类型菜单的鼠标提示
- `增加金币 10` 作为已经添加到列表中的实例摘要

这个特性可以用于三类自定义类型：

1. 继承 `DialogueEvent` 的自定义事件
2. 继承 `DialogueCondition` 的自定义条件
3. 继承 `DialogueNodeData` 的自定义节点

自定义节点添加该特性后，右键 GraphView 的创建节点菜单和节点标题都会使用自定义名称。自定义条件和事件添加到详情面板后，类型选择菜单和列表标题都会使用自定义名称。

如果不添加该特性，编辑器会退回使用类名的友好格式。`DialogueEditorName` 只改变编辑器显示文字，不改变序列化类型名，也不能避免重命名类或命名空间导致的 `[SerializeReference]` 数据迁移问题。

### 自定义节点示例

```csharp
using System;
using DialogueSystem;

[Serializable]
[DialogueEditorName("播放音效", "播放指定的音频片段")]
public class PlaySoundNode : DialogueNodeData
{
    public string clipId;

    public override string GetSummary()
    {
        return string.IsNullOrEmpty(clipId) ? "未设置音效" : $"音效: {clipId}";
    }
}
```

> 编辑器显示名称和实例摘要是两层设置：`DialogueEditorName` 负责“类型叫什么”，`GetSummary()` 负责“当前这个实例配置了什么”。

## 9. 编写自定义条件

条件和事件的添加方式一致，但继承的是 `DialogueCondition`，并实现 `Evaluate`。

### 示例：金币足够

```csharp
using System;
using DialogueSystem;

[Serializable]
public class GoldAtLeastCondition : DialogueCondition
{
    public int amount = 50;

    public override bool Evaluate(DialogueContext context)
    {
        return context.Blackboard.GetInt("gold") >= amount;
    }

    public override string GetSummary()
    {
        return $"金币 >= {amount}";
    }
}
```

编译成功后，在任意选择的 `Conditions` 列表点击 `+`，就可以选择 `GoldAtLeastCondition`。

### 示例：检查字符串标记

当前 `Blackboard` 提供 `GetString` / `SetString`，可以按项目需求编写条件：

```csharp
using System;
using DialogueSystem;

[Serializable]
public class StringEqualsCondition : DialogueCondition
{
    public string key;
    public string expectedValue;

    public override bool Evaluate(DialogueContext context)
    {
        return context.Blackboard.GetString(key) == expectedValue;
    }

    public override string GetSummary()
    {
        return $"{key} == {expectedValue}";
    }
}
```

### 在选择节点中使用自定义条件

1. 点击目标选择节点。
2. 展开 `Choices`。
3. 展开目标 `ChoiceOption`。
4. 在它自己的 `Conditions` 列表点击 `+`。
5. 选择刚编译完成的自定义条件。
6. 填写条件字段。
7. 保存并运行测试。

## 10. 状态分支节点的条件

状态分支节点与选择条件使用同一套 `DialogueCondition`，但用途不同：

- 选择条件：决定某个选项是否显示。
- 分支条件：决定运行时沿哪一条输出端口继续。

### 添加分支

1. 创建 `StateBranchNode`。
2. 点击节点，在详情面板展开 `Cases`。
3. 点击 `+` 添加一个 `BranchCase`。
4. 填写 `Label`，方便在图上识别。
5. 在该分支自己的 `Conditions` 列表中添加条件。
6. 将分支端口连接到对应后续节点。
7. 最后一个端口是“默认”端口，连接兜底路径。

### 分支匹配规则

- 分支从上到下检查。
- 每条分支有自己的“**条件组合**”下拉：**并（All，默认）**要求该分支所有条件全部满足；**或（Any）**任一条件满足即命中（空元素忽略）。
- 命中第一条满足条件的分支后就停止继续检查。
- 所有分支都不满足时走“默认”端口。
- 空条件分支不会命中；需要兜底时请连接“默认”端口，不要创建空条件分支冒充默认。

## 11. 随机分支节点

随机分支节点用于“多条路里随机走一条”的场景：NPC 随机闲聊、随机遭遇、随机奖励线路等。它与状态分支节点共用同一套分支条件，但**判定方式不同**：

- 状态分支：自上而下取**第一条**满足条件的分支。
- 随机分支：在**所有**满足条件的分支中**等概率随机**选一条。

### 添加随机分支

1. 创建 `RandomBranchNode`（右键菜单选“随机分支节点”）。
2. 点击节点，在详情面板展开 `Cases`。
3. 点击 `+` 添加分支，填写 `Label` 方便识别。
4. 需要限制的分支在它自己的 `Conditions` 列表添加条件（支持并/或组合，用法与状态分支一致）。
5. 将每个分支端口连接到对应后续节点。
6. 最后一个端口是“**默认**”端口：所有分支都有条件且全不满足时走这里，连接兜底路径。

### 与状态分支的两个重要区别

1. **无条件分支永远参与随机**。状态分支里空条件分支永不命中；随机分支里不挂条件的分支等于“无条件，直接进随机池”。所以纯随机场景（商人随机说三句话）只要建三条不挂条件的分支即可，不需要写任何条件。
2. **没有“自上而下”的优先级**。命中集合里所有分支等概率，分支排列顺序不影响结果。

### 随机复现（测试/回放）

随机源是全局共享的 `System.Random`。需要在测试或回放中复现同一随机序列时，在 `Play` 之前重置种子：

```csharp
RandomBranchNode.ResetSeed(42);   // 影响所有随机分支节点
player.Play(dialogueAsset, context);
```

### 常见问题

- **每次都走同一条分支？** 检查是否只有一条分支满足条件（其他分支的条件把她们过滤掉了），或其余分支条件写反。
- **走了默认端口？** 说明所有分支都有条件且全部不满足。要么放宽条件，要么把其中一条分支改为无条件（参与随机）。
- **想控制权重（某条更容易中）？** 当前为等概率；可以临时用多条相同分支近似权重（如 2 条 A + 1 条 B ≈ A 的概率是 B 的两倍）。

## 12. 运行时接入

播放器通过事件把对话内容交给自己的 UI。选择节点不再传递说话者和正文，选择前需要通过前置 `DialogueNode` 显示提示。

```csharp
var context = new DialogueContext();
context.Blackboard.SetInt("gold", 100);
context.Blackboard.SetBool("talked_to_guard", true);

var player = new DialoguePlayer();

player.OnDialogue += (speaker, text, continueCallback) =>
{
    // 显示说话者和文本。
    // 玩家点击继续时调用 continueCallback();
};

player.OnChoice += (choices, chooseCallback) =>
{
    // 显示 choices。
    // choices[i].choiceIndex 是选择节点中的原始下标。
    // 玩家点击某项时调用 chooseCallback(choices[i].choiceIndex)。
};

player.OnWait += (seconds, continueCallback) =>
{
    // 隐藏 UI，等待 seconds 秒后调用 continueCallback()。
};

player.OnEnd += () =>
{
    // 隐藏对话 UI。
};

player.Play(dialogueAsset, context);
```

### 重要的选择回调规则

- 不要把可见列表的数组下标直接当作图端口下标。
- 必须使用 `ChoiceInfo.choiceIndex` 调用选择回调。
- 例如条件隐藏了原始下标 0 后，界面上第一个可见按钮可能对应原始下标 1。

## 13. 导出对话文本到 Excel

菜单:`Tools → Dialogue System → 导出对话文本到 Excel`

### 操作步骤

1. 点击菜单后先**选择文件夹**(必须是工程 `Assets` 内的路径,支持子文件夹递归扫描)。
2. 工具会扫描文件夹内所有 `Dialogue Graph` 资产,提取:
   - **对话节点**的正文(带说话者)
   - **选择节点**每个选项的文本
3. **相同文本自动去重**:按去除首尾空白后的全文比较,重复的只保留第一条;空白文本直接跳过。
4. 选择保存位置(默认文件名 `DialogueTexts_日期_时间.xlsx`),导出完成弹窗显示统计。
5. Excel 列:序号 / 类型(对话、选项)/ 说话者 / 文本内容 / 来源资产;表头加粗,首行冻结。

### 适合的使用场景

- 交给策划/翻译/配音对文本:一张表看全部台词。
- 检查重复文案:去重后的表就是“当前全部不同文本”清单。
- 音频字幕制作:按“文本内容”列逐条配音。

### 注意事项

- 依赖 `Assets/Plugins/NPOI`(NuGet 的 NPOI 2.x Unity 版);仅编辑器使用,**运行时不依赖任何第三方库**。
- 导出的只是文本快照;修改对话后需要重新导出。
- 如果保存到 `Assets` 内,AssetDatabase 会自动刷新让文件立即可见;保存到工程外也可以(如桌面)。

## 14. 常见问题排查

### 选择节点没有显示正文

这是预期行为。选择节点只管理选项。请在它前面放一个 `DialogueNode`，将正文写在对话节点中。

### 选择节点没有可用选项

检查：

1. `Choices` 是否为空。
2. 每个 `ChoiceOption` 的 `Choice Text` 是否填写。
3. 条件的 Key 是否与运行时写入的 Key 完全一致。
4. `IntCompareCondition` 的运算符和值是否正确。
5. 任务 ID 是否大小写完全一致。
6. 是否初始化并传入了正确的 `DialogueContext`。

如果所有选项都被条件过滤，播放器会触发 `OnEnd`。

### 事件没有效果

检查：

1. 事件节点是否在开始节点可到达的连线上。
2. 事件节点是否真的连到了后续节点。
3. 事件节点是否选择了事件类型（标题显示“事件节点(未选类型)”表示还没选）。
4. 事件的 Key、Quest Id 是否与条件使用的键完全一致。
5. 自定义事件的代码是否在 `Execute` 中真正修改了状态。
6. 是否在事件节点之前就触发了 `EndNode` 或跳转。

### 修改文本后高度不变

先点击其他节点再重新点击对话节点，确认详情面板绑定的是当前节点；然后检查 Console 是否存在编译错误。正常情况下，正文会按内容自动扩展，并保留最小高度。

### 修改或重命名自定义类后数据丢失

节点、条件和事件使用 `[SerializeReference]`。Unity 按类名和命名空间保存类型，直接重命名可能导致原有数据无法反序列化。需要重命名时使用 `MovedFromAttribute` 设计兼容迁移，或在改名前备份资产。

## 15. 推荐的编辑检查清单

保存前逐项检查：

- [ ] 每张图都有唯一的开始节点。
- [ ] 开始节点已经连接到第一个实际节点。
- [ ] 所有对话节点的 `Speaker Name` 和 `Dialogue Text` 已填写。
- [ ] 选择节点前有对话节点时，提示正文写在前置对话节点中。
- [ ] 每个选择端口都连到了预期的后续节点。
- [ ] 需要限制的选择只在自己的 `Conditions` 列表添加条件。
- [ ] 一个选择/分支的多个条件的“条件组合”（并/或）符合预期。
- [ ] 每个事件节点都已选择事件类型并填好字段。
- [ ] 事件使用的 Key / Quest Id 与条件和运行时代码完全一致。
- [ ] 状态分支节点已经连接默认端口。
- [ ] 节点没有孤立在开始节点不可达的区域。
- [ ] 点击“保存”，顶部显示“已保存”。
