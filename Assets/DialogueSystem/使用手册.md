# DialogueSystem 对话节点编辑器使用手册

本文档适用于 `Assets/DialogueSystem`。它说明如何创建对话图、编辑节点、添加事件，以及为**选择节点中的每一个选择**配置条件。

> 当前版本的职责划分：
> - `DialogueNode`：负责说话者和对话文本。
> - `ChoiceNode`：只负责选项和选项条件，不再包含 `Speaker Name`、`Dialogue Text`。
> - 如果需要“先说一段话，再让玩家选择”，请把一个 `DialogueNode` 连到 `ChoiceNode`。

---

## 1. 安装与打开编辑器

1. 将整个 `Assets/DialogueSystem` 文件夹复制到 Unity 工程的 `Assets` 目录下。
2. 等待 Unity 编译完成，确认 Console 没有红色编译错误。
3. 在 Project 窗口空白处右键，选择：

   `Create → Dialogue System → Dialogue Graph`

4. 双击创建出来的资产，打开 `Dialogue Graph` 编辑器。
5. 也可以通过菜单打开：

   `Window → Dialogue System → Dialogue Graph`

6. 如果使用菜单打开，先在窗口顶部的“对话资产”栏中拖入一个 `Dialogue Graph` 资产。

### 保存方式

- 新建节点、移动节点、连线、修改字段都会让顶部状态变成“有未保存修改”。
- 点击顶部的“保存”按钮，或使用 `Ctrl + S`（macOS 为 `Cmd + S`）保存。
- 切换对话资产或关闭窗口时，如果还有未保存修改，编辑器会询问是否保存。
- “聚焦全部”按钮可以让右侧图视图自动显示所有节点。

---

## 2. 节点类型与推荐连接方式

| 节点 | 作用 | 输出端口 |
| --- | --- | --- |
| 开始 | 固定入口，每张图唯一，不可删除 | 下一个 |
| 对话 | 显示说话者和一段对话文本 | 下一个 |
| 选择 | 显示多个选项，每个选项一个端口 | 每个选项一个 |
| 状态分支 | 按条件从上到下选择第一条命中的分支 | 每条分支 + 默认 |
| 事件 | 按列表顺序执行事件 | 下一个 |
| 等待 | 等待指定秒数后继续 | 下一个 |
| 跳转 | 跳转到另一张对话图的入口 | 无 |
| 结束 | 明确结束当前对话 | 无 |

### 最常见的对话结构

```text
开始 → 对话 → 选择
              ├─ 选项 0 → 对话 → 结束
              ├─ 选项 1 → 事件 → 对话 → 结束
              └─ 选项 2 → 结束
```

选择节点本身不再保存说话者和对话文本。因此推荐这样组织：

```text
对话节点(“村长”：你想做什么？) → 选择节点(接取任务 / 离开)
```

这样每个节点只承担一种职责，详情面板也更清晰。

### 创建和连接节点

1. 在右侧图区域空白处点击右键。
2. 在“创建对话节点”菜单中选择节点类型。
3. 拖动节点的输出端口到另一个节点的输入端口。
4. 一个普通节点只有一个输入端口；同一个节点不应连接多个前置节点。
5. 选择节点和状态分支节点的输出端口顺序与左侧列表顺序一致，修改列表顺序后请检查连线。
6. 删除连线：选中连线后按 `Delete`。
7. 删除普通节点：选中节点后按 `Delete`。开始节点由编辑器保护，不能删除。

---

## 3. 对话节点：编辑说话者和正文

1. 点击图中的“对话节点”。
2. 在左侧“节点详情”中填写：
   - `Speaker Name`：说话者名称，例如“村长”“商人”。
   - `Dialogue Text`：对话正文。
   - `Voice Clip`：可选语音片段。
3. `Dialogue Text` 会根据输入内容、换行和自动换行结果自动增高。
4. 文本框有最小高度，不会因为内容较短而缩得过小；输入长段落时会继续扩展。
5. 点击保存。

### 文本编辑建议

- 一段独立显示的台词使用一个 `DialogueNode`。
- 不要把多个不同角色的台词塞进同一个节点；这样无法逐句控制玩家点击“继续”的时机。
- 需要换行时可以直接在 `Dialogue Text` 中按 Enter。
- 需要选项提示时，先用对话节点显示提示，再连接选择节点。

## 4. 选择节点：添加选项

选择节点的详情面板只显示 `Choices` 列表，不显示 `Speaker Name` 和 `Dialogue Text`。

### 添加一个选择

1. 创建一个 `ChoiceNode`。
2. 点击选择节点，在左侧找到 `Choices`。
3. 展开 `Choices` 列表。
4. 点击列表右下角的 `+` 添加一个 `ChoiceOption`。
5. 在新增元素的 `Choice Text` 中输入玩家看到的文字，例如：
   - `接取任务`
   - `去商店`
   - `离开`
6. 再次点击 `+` 可以继续添加更多选择。
7. 选择列表的下标就是输出端口编号：
   - 第 0 个选择 → 输出端口 0
   - 第 1 个选择 → 输出端口 1
   - 第 2 个选择 → 输出端口 2
8. 将每个输出端口分别连接到对应的后续节点。
9. 保存。

### 选择条件的基本规则

- 每一个 `ChoiceOption` 都有自己独立的 `Conditions` 列表。
- `Conditions` 为空：该选择无条件，始终显示。
- 一个选择有多个条件：**所有条件都满足**时才显示，条件之间是 AND 关系。
- 条件不满足时，运行时会隐藏该选择，但不会改变其他选择的下标。
- 回调使用的是原始选择下标，所以隐藏选项不会导致后续连线错位。
- 如果运行时没有任何选择满足条件，对话会结束。若需要兜底路线，建议使用状态分支节点或添加一个无条件的“离开/返回”选项。

### 给某一个选择添加条件

以“去商店，金币至少 50”为例：

1. 点击选择节点。
2. 展开 `Choices`。
3. 展开要限制的那个 `ChoiceOption`。
4. 在该选项的 `Conditions` 列表右下角点击 `+`。
5. 在类型选择菜单中选择 `IntCompareCondition`。
6. 设置：
   - `Key` = `gold`
   - `Op` = `GreaterOrEqual`
   - `Value` = `50`
7. 保存。
8. 运行对话前，游戏代码需要把当前金币写入上下文：

```csharp
var context = new DialogueContext();
context.Blackboard.SetInt("gold", 100);
player.Play(dialogueAsset, context);
```

此时金币为 100 时“去商店”显示；金币为 49 时该选择隐藏。

### 给同一个选择添加多个条件

例如“只有金币至少 50 且任务已经完成”才能选择：

```text
ChoiceOption: 去商店
└─ Conditions
   ├─ IntCompareCondition: gold >= 50
   └─ QuestStateCondition: shop_quest == Completed
```

操作步骤：

1. 在同一个 `ChoiceOption` 的 `Conditions` 列表添加第一个条件。
2. 再次点击同一个列表的 `+`。
3. 添加第二个条件。
4. 两个条件都会满足时，这个选择才会显示。

不要把条件加到另一个 `ChoiceOption` 上；每个选项的条件列表是独立的。

## 5. 内置条件的写法与使用

### 5.1 `IntCompareCondition`：比较整数

用于金币、分数、等级、好感度、计数器等整数值。

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `Key` | 黑板整数的键 | `gold` |
| `Op` | 比较运算符 | `GreaterOrEqual` |
| `Value` | 比较目标值 | `50` |

可用运算符：

| 枚举值 | 实际含义 |
| --- | --- |
| `Equal` | `==` |
| `NotEqual` | `!=` |
| `Less` | `<` |
| `LessOrEqual` | `<=` |
| `Greater` | `>` |
| `GreaterOrEqual` | `>=` |

运行时代码示例：

```csharp
context.Blackboard.SetInt("gold", 100);
context.Blackboard.SetInt("player_level", 8);
```

编辑器配置示例：

```text
Key = player_level
Op = GreaterOrEqual
Value = 5
```

含义是：玩家等级大于等于 5 时满足。

### 5.2 `BoolFlagCondition`：比较布尔标记

用于门是否打开、是否看过某段剧情、是否拥有某个能力等。

```text
Key = talked_to_guard
Expected Value = true
```

运行时代码：

```csharp
context.Blackboard.SetBool("talked_to_guard", true);
```

条件含义是：`talked_to_guard == true`。

### 5.3 `QuestStateCondition`：判断任务状态

可选状态：

- `NotStarted`：未接取
- `Active`：进行中
- `Completed`：已完成

编辑器配置示例：

```text
Quest Id = dragon_quest
Required Status = Completed
```

运行时代码或事件可以写入任务状态：

```csharp
context.Quests.AddQuest("dragon_quest");
context.Quests.CompleteQuest("dragon_quest");
```

任务 ID 必须完全一致，包括大小写和下划线。

## 6. 事件节点：添加事件

事件节点会在运行时自动执行事件列表，然后从“下一个”端口继续。事件按照列表从上到下、从 0 到最后一个的顺序执行。

### 添加事件的通用步骤

1. 在图中创建 `EventNode`。
2. 点击事件节点，在左侧详情中找到 `Events` 列表。
3. 点击 `Events` 列表右下角的 `+`。
4. 在类型选择菜单中选择事件类型。
5. 展开新增事件，填写它的字段。
6. 再次点击 `+` 可以添加第二个、第三个事件。
7. 按列表顺序检查事件执行顺序。
8. 将事件节点的“下一个”端口连接到后续节点。
9. 保存。

### 6.1 `AddQuestEvent`：接取任务

添加步骤：

1. 在 `Events` 列表点击 `+`。
2. 选择 `AddQuestEvent`。
3. 设置 `Quest Id`，例如 `dragon_quest`。
4. 运行到该节点时，相当于：

```csharp
context.Quests.AddQuest("dragon_quest");
```

### 6.2 `CompleteQuestEvent`：完成任务

添加步骤：

1. 在 `Events` 列表点击 `+`。
2. 选择 `CompleteQuestEvent`。
3. 设置与接取任务时完全相同的 `Quest Id`。
4. 运行到该节点时，相当于：

```csharp
context.Quests.CompleteQuest("dragon_quest");
```

### 6.3 `SetIntEvent`：设置整数

添加步骤：

1. 在 `Events` 列表点击 `+`。
2. 选择 `SetIntEvent`。
3. 设置：
   - `Key` = `gold`
   - `Value` = `0`
4. 运行到该节点时，相当于：

```csharp
context.Blackboard.SetInt("gold", 0);
```

> `SetIntEvent` 是“直接设置”，不是“增加或减少”。如果需要 `gold += 10`，请编写自定义事件，或在自己的游戏状态系统中实现对应逻辑。

### 6.4 在一个事件节点中组合多个事件

例如完成任务后把金币设为 100，再跳到一段对话：

```text
EventNode
└─ Events
   ├─ CompleteQuestEvent { questId = dragon_quest }
   └─ SetIntEvent       { key = gold, value = 100 }
```

执行顺序是：

1. 完成 `dragon_quest`。
2. 设置 `gold` 为 100。
3. 执行下一个节点。

如果后续节点的条件依赖前一个事件修改的状态，把修改状态的事件放在前面。

## 7. 编写自定义事件

当内置事件不能满足需求时，继承 `DialogueEvent`。自定义事件必须满足：

- 类使用 `[Serializable]`。
- 继承 `DialogueEvent`。
- 实现 `Execute(DialogueContext context)`。
- 文件放在工程 `Assets` 下并成功编译。
- 类不是抽象类，并且可以被 Unity 序列化。

### 示例：增加金币

将下面脚本保存为：

`Assets/Scripts/Dialogue/AddGoldEvent.cs`

```csharp
using System;
using DialogueSystem;

[Serializable]
public class AddGoldEvent : DialogueEvent
{
    public int amount = 10;

    public override void Execute(DialogueContext context)
    {
        var current = context.Blackboard.GetInt("gold");
        context.Blackboard.SetInt("gold", current + amount);
    }

    public override string GetSummary()
    {
        return $"金币 += {amount}";
    }
}
```

### 示例：设置布尔标记

```csharp
using System;
using DialogueSystem;

[Serializable]
public class SetFlagEvent : DialogueEvent
{
    public string key;
    public bool value = true;

    public override void Execute(DialogueContext context)
    {
        context.Blackboard.SetBool(key, value);
    }

    public override string GetSummary()
    {
        return $"{key} = {value}";
    }
}
```

### 示例：调用自己的游戏系统

如果项目中有任务管理器、背包系统或剧情管理器，可以在 `Execute` 中调用它们：

```csharp
using System;
using DialogueSystem;

[Serializable]
public class UnlockDoorEvent : DialogueEvent
{
    public string doorId;

    public override void Execute(DialogueContext context)
    {
        // 替换为项目实际的门系统调用。
        // DoorManager.Instance.Unlock(doorId);
    }

    public override string GetSummary()
    {
        return $"解锁门[{doorId}]";
    }
}
```

> `Execute` 是运行时调用，不是在编辑器里点击 `+` 时执行。编辑器中的字段只是把事件数据保存到对话资产。

### 自定义事件添加不到列表时

按以下顺序检查：

1. Console 是否有红色编译错误。
2. 类是否继承了正确的 `DialogueSystem.DialogueEvent`。
3. 是否加了 `[Serializable]`。
4. 类是否为 `public`、非 `abstract`。
5. 脚本是否放在 `Assets` 目录下。
6. 保存脚本后等待 Unity 编译完成，再重新展开 `Events` 列表。
7. 如果事件类名或命名空间已经被改过，旧的 `[SerializeReference]` 数据可能无法恢复；正式项目应使用 Unity 的 `MovedFromAttribute` 做兼容迁移。

## 8. 编写自定义条件

条件和事件的添加方式一致，但继承的是 `DialogueCondition`，并实现 `Evaluate`。

### 示例：金币足够

```csharp
using System;
using DialogueSystem;

[Serializable]
public class GoldAtLeastCondition : DialogueCondition
{
    public int amount = 50;

    public override bool Evaluate(DialogueContext context)
    {
        return context.Blackboard.GetInt("gold") >= amount;
    }

    public override string GetSummary()
    {
        return $"金币 >= {amount}";
    }
}
```

编译成功后，在任意选择的 `Conditions` 列表点击 `+`，就可以选择 `GoldAtLeastCondition`。

### 示例：检查字符串标记

当前 `Blackboard` 提供 `GetString` / `SetString`，可以按项目需求编写条件：

```csharp
using System;
using DialogueSystem;

[Serializable]
public class StringEqualsCondition : DialogueCondition
{
    public string key;
    public string expectedValue;

    public override bool Evaluate(DialogueContext context)
    {
        return context.Blackboard.GetString(key) == expectedValue;
    }

    public override string GetSummary()
    {
        return $"{key} == {expectedValue}";
    }
}
```

### 在选择节点中使用自定义条件

1. 点击目标选择节点。
2. 展开 `Choices`。
3. 展开目标 `ChoiceOption`。
4. 在它自己的 `Conditions` 列表点击 `+`。
5. 选择刚编译完成的自定义条件。
6. 填写条件字段。
7. 保存并运行测试。

## 9. 状态分支节点的条件

状态分支节点与选择条件使用同一套 `DialogueCondition`，但用途不同：

- 选择条件：决定某个选项是否显示。
- 分支条件：决定运行时沿哪一条输出端口继续。

### 添加分支

1. 创建 `StateBranchNode`。
2. 点击节点，在详情面板展开 `Cases`。
3. 点击 `+` 添加一个 `BranchCase`。
4. 填写 `Label`，方便在图上识别。
5. 在该分支自己的 `Conditions` 列表中添加条件。
6. 将分支端口连接到对应后续节点。
7. 最后一个端口是“默认”端口，连接兜底路径。

### 分支匹配规则

- 分支从上到下检查。
- 一个分支的多个条件必须全部满足。
- 命中第一条满足条件的分支后就停止继续检查。
- 所有分支都不满足时走“默认”端口。
- 空条件分支不会命中；需要兜底时请连接“默认”端口，不要创建空条件分支冒充默认。

## 10. 运行时接入

播放器通过事件把对话内容交给自己的 UI。选择节点不再传递说话者和正文，选择前需要通过前置 `DialogueNode` 显示提示。

```csharp
var context = new DialogueContext();
context.Blackboard.SetInt("gold", 100);
context.Blackboard.SetBool("talked_to_guard", true);

var player = new DialoguePlayer();

player.OnDialogue += (speaker, text, continueCallback) =>
{
    // 显示说话者和文本。
    // 玩家点击继续时调用 continueCallback();
};

player.OnChoice += (choices, chooseCallback) =>
{
    // 显示 choices。
    // choices[i].choiceIndex 是选择节点中的原始下标。
    // 玩家点击某项时调用 chooseCallback(choices[i].choiceIndex)。
};

player.OnWait += (seconds, continueCallback) =>
{
    // 隐藏 UI，等待 seconds 秒后调用 continueCallback()。
};

player.OnEnd += () =>
{
    // 隐藏对话 UI。
};

player.Play(dialogueAsset, context);
```

### 重要的选择回调规则

- 不要把可见列表的数组下标直接当作图端口下标。
- 必须使用 `ChoiceInfo.choiceIndex` 调用选择回调。
- 例如条件隐藏了原始下标 0 后，界面上第一个可见按钮可能对应原始下标 1。

## 11. 常见问题排查

### 选择节点没有显示正文

这是预期行为。选择节点只管理选项。请在它前面放一个 `DialogueNode`，将正文写在对话节点中。

### 选择节点没有可用选项

检查：

1. `Choices` 是否为空。
2. 每个 `ChoiceOption` 的 `Choice Text` 是否填写。
3. 条件的 Key 是否与运行时写入的 Key 完全一致。
4. `IntCompareCondition` 的运算符和值是否正确。
5. 任务 ID 是否大小写完全一致。
6. 是否初始化并传入了正确的 `DialogueContext`。

如果所有选项都被条件过滤，播放器会触发 `OnEnd`。

### 事件没有效果

检查：

1. 事件节点是否在开始节点可到达的连线上。
2. 事件节点是否真的连到了后续节点。
3. 事件是否添加到了 `Events` 列表，而不是只创建了事件脚本。
4. 事件的 Key、Quest Id 是否与条件使用的键完全一致。
5. 自定义事件的代码是否在 `Execute` 中真正修改了状态。
6. 是否在事件节点之前就触发了 `EndNode` 或跳转。

### 修改文本后高度不变

先点击其他节点再重新点击对话节点，确认详情面板绑定的是当前节点；然后检查 Console 是否存在编译错误。正常情况下，正文会按内容自动扩展，并保留最小高度。

### 修改或重命名自定义类后数据丢失

节点、条件和事件使用 `[SerializeReference]`。Unity 按类名和命名空间保存类型，直接重命名可能导致原有数据无法反序列化。需要重命名时使用 `MovedFromAttribute` 设计兼容迁移，或在改名前备份资产。

## 12. 推荐的编辑检查清单

保存前逐项检查：

- [ ] 每张图都有唯一的开始节点。
